**Run an agentic coding LLM on the GPU you actually own — a home AMD RX 6600 with an 8GB budget box in a closet.**

No cloud. No rate limits. No $3/M token. Just llama.cpp on Vulkan, a few fiddly glue scripts, and two models that (mostly) remember how to call tools. Turn your LAN into an OpenAI-compatible endpoint and point [opencode](https://opencode.ai) at it.

---

## Why this exists

GPT-5-class agents are great until the invoice arrives. This project is the "we have AGI at home" answer: serve small open-weight models (7–8B) on consumer AMD GPUs over **Vulkan**, and make them participate in **real tool-calling agent loops** — not just chat. The models are cheap, the GPU was there already, and the only "cloud" is your own living room.

Everything here was learned the hard way on real hardware. The glue code exists because:

- llama.cpp's native server does **not** emit the OpenAI `tool_calls` JSON on the wire (it has its own tag format). The proxy fixes that.
- Several popular GGUFs ship with **gutted chat templates** — no tool namespace — so the model literally cannot express a tool call. One fix: re-inject the original template (see `llama/hermes2pro-tool.jinja`).
- Small models go into "greeter mode" (say hi, call nothing) when the agent's system prompt is huge. A short action directive fixes it.
- 8K-context models + an agent protocol that wants ~9K of tools alone = 400s. A [kompact](https://github.com/npow/kompact) compression proxy in front solves the context budget.

## How it works

```
                     your LAN                                 this server (127.0.0.1)
 ┌─────────────────────────┐     ┌──────────────┐   ┌────────────────────────┐   ┌────────────────┐   ┌──────────────┐
 │  opencode agent (any PC) │ ──► │  kompact     │ ─►│  toolup proxy          │ ─►│  llama-server  │ ─►│  RX 6600     │
 │  reads/writes files,     │     │  context     │   │  • rewrites tool_calls │   │  llama.cpp     │   │  Vulkan      │
 │  runs bash, chains tools │     │  compression │   │  • short system dir.   │   │  (native build)│   │  GPU         │
 └─────────────────────────┘     └──────────────┘   └────────────────────────┘   └────────────────┘   └──────────────┘
      http://LLM_SERVER_IP:8000/v1                    127.0.0.1:8001               127.0.0.1:8002
```

Layer by layer, from the GPU up:

1. **llama-server (port 8002)** — a prebuilt llama.cpp server with the Vulkan backend ([built `.so` files, no compilers needed](../install.sh)). `-ngl 99` pushes everything onto the GPU; ~40 tokens/s on a 7B Q4_K_M.
2. **toolup proxy (port 8001)** — teaches opencode's dialect of OpenAI to a model that speaks a different one:
   - Detects a tool call inside llama.cpp's raw output and rewrites it into the OpenAI `tool_calls` array (`finish_reason: "tool_calls"`), streaming or not.
   - Swaps an oversized agent system prompt for a short "take direct action" directive when it exceeds `SYSTEM_MAX` chars (default 1050) — this is what stops greeter-mode.
   - Auto-applies the correct chat template file for models that ship a gutted one.
3. **kompact (port 8000)** — [context-compression proxy](https://github.com/npow/kompact): TF-IDF schema optimization for the tool definitions, extractive/JSON/code compression, observation masking. Cuts token counts 40–70% so an 8K model survives a real agent session. Disable any transform via `LLM_KOMPACT_OPTS`.
4. **The LAN** — kompact binds `0.0.0.0:8000`, so any laptop on your network points its OpenAI-compatible client at `http://<server-ip>:8000/v1` and gets a working agent.

## Install

One free [Hugging Face token](https://huggingface.co/settings/tokens), one terminal:

```bash
git clone https://github.com/<you>/llm-for-the-poors.git && cd llm-for-the-poors
./install.sh                 # llama.cpp (Vulkan) + venv + kompact + HF token
./manage_deepseek.py install --quant Q2_5_C7B   # download your model (4.7 GB)
./llm.sh start               # full chain live on :8000
curl http://127.0.0.1:8000/health
```

`install.sh` grabs a [llama.cpp prebuilt Vulkan binary](https://github.com/ggml-org/llama.cpp/releases) (no compilers); if that ever disappears it falls back to building `llama-cpp-python` with Vulkan via `manage_deepseek.py install`.

### Point opencode at it

From any PC on the LAN:

```bash
curl -fsSL https://opencode.ai/install | bash     # or npm i -g opencode-ai
mkdir -p ~/.config/opencode
cp examples/opencode.jsonc ~/.config/opencode/opencode.jsonc
# edit the IP, then:
opencode run --model local/qwen "write hello.py and run it"
```

## Usage

```bash
./llm.sh start            # start the whole chain (kompact + proxy + llama-server)
./llm.sh stop
./llm.sh status
./manage_deepseek.py status          # model + backend
./manage_deepseek.py chat            # bare interactive session
./manage_deepseek.py verify          # GPU smoke test + tokens/sec
./manage_deepseek.py serve ...       # (llm.sh wraps this)
python3 agent.py "solve 5*7 with the python tool"
```

### Tuning knobs

| env var | default | what it does |
|---------|---------|--------------|
| `LLM_CTX` | `16384` | context window passed to llama-server |
| `LLM_KOMPACT_OPTS` | `--no-otel --disable observation_masker --disable cache_aligner` | kompact transform on/off switches |
| `SYSTEM_MAX` | `1050` | agent system prompt length threshold before the short-directive swap |
| `LLAMA_SERVER_DIR` | `llama/llama-native` | where the prebuilt llama-server lives |
| `LLAMA_CHAT_TEMPLATE_FILE` | auto (Hermes) | custom chat-template jinja to auto-apply |
| `KOMPACT` | `~/kompact/bin/kompact` | kompact binary path |

## Known limitations (truth in advertising)

- **It's 7–8B on a budget GPU.** Tools get called, steps get executed, and sometimes the model wanders off, echoes its system prompt, or "greets" you instead of working. That's the model ceiling, not a bug in the plumbing. Budget quality: ~"junior dev, most of the time."
- **Vulkan, not CUDA.** Works on AMD/Intel; an NVIDIA box would use CUDA, but that's another README.
- **Hermes and Llama-3.1 GGUFs cap at 8192 tokens.** YaRN rope-scaling flags are accepted by llama-server but don't extend the trained context on these builds.
- **`agent.py` runs Python with no sandbox** (`python -c '...'`). It's a personal toy agent — don't feed it untrusted prompts.
- Your `HF_TOKEN` lands in `~/.zshrc`/`~/.bashrc` — keep that shell private.
